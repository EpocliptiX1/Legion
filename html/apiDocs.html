API Documentation

Embed movies, TV shows, and anime on your own site through AniKino - one iframe, one URL, pulling from our Mega, KAA, Neko, RU MV, and Kino sources under the hood so you don't have to juggle providers yourself.

✅
The core embed endpoints below are live and working - every example on this page is a real, tested URL. What's still not built: autoplay/startAt/autonext query params, player postMessage events, and resume-playback (see their own sections further down) - those stay marked TBD.

Introduction

Drop a single <iframe> into your own site and get a fully working AniKino player back - no API key, no sign-up. Every embed resolves the real stream server-side and serves it through AniKino's own Plyr-based player, not a nested third-party iframe - the actual provider CDN URL is never exposed to your page or your visitors.

Movie TV Show Anime 
<iframe
  src="https://your-domain.example/embed/movie/293660"
  width="100%" height="560"
  frameborder="0" allowfullscreen
></iframe>
🆔
Every {id} below accepts either a numeric TMDB id or an IMDB id (tt1300854-style) - both are resolved automatically, no need to tell us which one you're sending.
🐢
/embed/* is rate-limited to 40 requests / 5 minutes per IP - plenty for a real viewer loading/reloading a player, not enough for bulk scraping. It's also the only part of AniKino's API that's deliberately reachable cross-origin; everything else is locked to our own frontend.

Providers

Each embed type has its own default source and an alternate you can force with ?server=. Anime and Movie/TV don't share providers - the same server=ru value means a different backend depending on which embed you're calling, both labeled RU MV on the frontend since they're both "the Russian-dub source" for their respective content type.

Mega anime, default

MegaPlay - broad anime coverage, usually the fastest to resolve.

server=mega

KAA anime

KickAssAnime - our most stable anime source, slower to load initially.

server=kaa

Neko anime

NekoStream/VidTube - faster than KAA, can go unavailable on some titles (falls back to Mega automatically when that happens).

server=neko

RU MV anime

animego.me → aniboom.one - Russian dub. Only available when animego's own title match is confident; falls through to an error otherwise rather than guessing wrong.

server=ru

Kino movie/TV, default

vidsrcme.ru-backed extraction - our primary movie/TV source, broad English-language coverage.

server=kino

RU MV movie/TV

kinogo.mu → cinemar.cc - Russian dub, single track, no subtitles of its own.

server=ru
GET /embed/movie/{id}

Movie Embed

Embed a movie player. Resolves through Kino (default) or RU MV/kinogo.

ParameterRequiredDescription
{id}YesTMDB movie id or IMDB id (tt...)
serverOptionalkino (default) or ru - see Providers
HTML URL 
<iframe src="https://your-domain.example/embed/movie/293660" width="100%" height="560" allowfullscreen></iframe>

# By IMDB id
/embed/movie/tt4425200

# Force the RU MV (kinogo) source
/embed/movie/293660?server=ru
GET /embed/tv/{id}/{season}/{episode}

Anime Embed

Embed an anime episode with sub/dub selection, resolved through Mega (default), KAA, Neko, or RU MV/animego.

ParameterRequiredDescription
{id}YesTMDB TV id or IMDB id (tt...) - anime is always the TV namespace, even for movies
{episode}YesEpisode number within season
seasonOptionalDefaults to 1
audioOptionalsub (default) or dub
serverOptionalmega (default), kaa, neko, or ru - see Providers
HTML URL 
<iframe src="https://your-domain.example/embed/anime/1429/1?season=1&audio=dub" width="100%" height="560" allowfullscreen></iframe>

# Sub, season 2, forced KickAssAnime
/embed/anime/1429/1?season=2&server=kaa

# Dub, NekoStream (falls back to Mega automatically if unavailable)
/embed/anime/1429/1?audio=dub&server=neko

# RU MV (animego) - only succeeds when animego has a confident title match
/embed/anime/1429/1?server=ru
💬
Captions are borrowed from KAA's own (usually multi-language) subtitle set regardless of which server you pick, since Mega/Neko/RU MV don't carry a useful subtitle track of their own. Kino (movie/TV) instead pulls real OpenSubtitles-backed captions directly.

Security

The raw upstream stream URL is never exposed anywhere - not in the page source, not in a JSON response, not at any layer of a nested playlist. Every embed resolves the real stream server-side and hands the player a session-bound, encrypted, expiring proxy URL instead - only /api/m3u8-proxy ever talks to the real CDN, and only for the exact browser session that resolved it. Copying a resolved stream URL out of your browser's network tab and loading it in a different browser/session returns 403 This link does not belong to your session - verified live.

The player itself carries a self-healing "AniKino" watermark (re-inserts itself if removed via a MutationObserver + interval respawn) - this defends against someone scraping the embed page's HTML and re-serving a modified copy with the branding stripped while keeping the player logic intact. A true cross-origin <iframe> can't be reached by whatever page embeds it at all, by normal browser same-origin policy - that protection needs nothing from us.
